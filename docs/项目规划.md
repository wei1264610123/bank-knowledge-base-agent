# 银行知识库智能问答系统 - 项目规划

## 一、项目概述

**项目名称**：BankKB-QA（银行知识库智能问答系统）

**项目目标**：基于LangChain框架，构建一个企业级的银行知识库问答系统，帮助银行客服人员快速、准确地回答用户关于银行相关问题。

**核心价值**：
- 提升客服响应效率
- 保证回答准确性和一致性
- 支持多轮对话，理解上下文
- 知识库集中管理，便于维护

## 二、技术选型方案

### 2.1 后端技术栈

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| **Python 3.11+** | 主开发语言 | LangChain原生支持，AI生态完善 |
| **FastAPI** | Web框架 | 高性能、自动文档、异步支持 |
| **LangChain** | AI框架 | 链式调用、RAG支持、模块化设计 |
| **SQLAlchemy** | ORM框架 | 数据库抽象、异步支持 |
| **Alembic** | 数据库迁移 | 版本控制、平滑升级 |
| **Pydantic** | 数据校验 | 类型安全、FastAPI原生集成 |
| **Celery** | 异步任务队列 | 文档处理、批量操作 |

### 2.2 数据库选型

| 数据库 | 用途 | 选型理由 |
|--------|------|----------|
| **PostgreSQL** | 主数据库 | 企业级、稳定可靠、JSON支持 |
| **Redis** | 缓存/会话 | 高性能、会话管理、消息队列 |
| **Milvus** | 向量数据库 | 专业向量检索、高并发支持 |

### 2.3 前端技术栈

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| **Vue 3** | 前端框架 | 响应式、组合式API、易维护 |
| **Element Plus** | UI组件库 | 企业级、组件丰富、美观 |
| **TypeScript** | 类型安全 | 代码质量、IDE支持 |
| **Pinia** | 状态管理 | Vue3官方推荐、轻量 |
| **Axios** | HTTP客户端 | 拦截器、取消请求、错误处理 |

### 2.4 基础设施

| 技术 | 用途 | 选型理由 |
|------|------|----------|
| **Docker** | 容器化 | 环境一致性、易于部署 |
| **Docker Compose** | 编排 | 开发环境一键启动 |
| **Nginx** | 反向代理 | 负载均衡、静态资源 |

## 五、数据模型设计

### 5.1 核心表结构

#### users（用户表）
```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) DEFAULT 'user',  -- 'admin', 'user'
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### chat_sessions（会话表）
```sql
CREATE TABLE chat_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    title VARCHAR(200),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### chat_messages（消息表）
```sql
CREATE TABLE chat_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID NOT NULL REFERENCES chat_sessions(id),
    role VARCHAR(20) NOT NULL,  -- 'user', 'assistant'
    content TEXT NOT NULL,
    references JSONB,  -- 引用的知识库片段
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### documents（文档表）
```sql
CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    filename VARCHAR(255) NOT NULL,
    file_path VARCHAR(500) NOT NULL,
    file_size INTEGER,
    file_type VARCHAR(50),
    category_id UUID,
    status VARCHAR(20) DEFAULT 'pending',  -- 'pending', 'processing', 'completed', 'failed'
    chunk_count INTEGER DEFAULT 0,
    created_by UUID REFERENCES users(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### document_chunks（文档分块表）
```sql
CREATE TABLE document_chunks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id UUID NOT NULL REFERENCES documents(id),
    content TEXT NOT NULL,
    chunk_index INTEGER NOT NULL,
    embedding_id VARCHAR(100),  -- Milvus中的向量ID
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

#### categories（分类表）
```sql
CREATE TABLE categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(100) NOT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 6.3 引用标注实现

```python
def format_references(retrieved_docs):
    """格式化引用来源"""
    references = []
    for doc in retrieved_docs:
        ref = {
            "content": doc.page_content[:200],  # 截取前200字
            "source": doc.metadata.get("source", "未知来源"),
            "page": doc.metadata.get("page", "N/A"),
            "score": doc.metadata.get("score", 0)
        }
        references.append(ref)
    return references
```

## 十一、安全设计

### 11.1 认证安全
- JWT Token有效期：2小时
- Refresh Token有效期：7天
- 密码使用bcrypt加密
- 支持Token刷新机制

### 11.2 数据安全
- SQL注入防护（SQLAlchemy ORM）
- XSS防护（前端输出转义）
- CSRF防护（SameSite Cookie）
- 文件上传限制（类型、大小）

### 11.3 API安全
- 请求频率限制（Rate Limiting）
- CORS配置
- 输入参数校验（Pydantic）
- 错误信息脱敏

## 十四、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| LLM API不稳定 | 服务不可用 | 多模型切换、本地模型备选 |
| 知识库数据质量差 | 回答不准确 | 数据清洗、人工审核 |
| 向量检索慢 | 响应延迟 | 索引优化、缓存策略 |
| 并发量大 | 服务压力 | 负载均衡、限流策略 |
| 数据泄露 | 安全风险 | 加密存储、访问控制 |
